<objective>
Create the Phase-1 stub of `src/core/reviews.js` — the new core module that owns
the `Reviews/` filesystem region. Phase 3 will grow this module with the
self-review writer; Phase 1 seeds it with just the `ensureReviewsDir(vaultPath)`
helper so it has a home to grow into.

The helper is the "suspenders" half of D-09: belt = `init` adds Reviews/ for new
vaults (Plan 01-03), suspenders = `ensureReviewsDir` covers users who never
re-run `init` after installing the milestone (so Phase 3 can call it
unconditionally before writing any `Reviews/<YYYY>-cycle<N>.md` file).

`paths.js#getVaultPath()`. This is deliberate: Phase 3's `self-review` command
runs after `applyUserConfig`, but the helper's contract should not depend on
module-level mutable state. Keeping the parameter explicit makes the function
testable without setting up the `paths.js` `activeVaultPath`.

    import { test, before, after } from 'node:test';
    import assert from 'node:assert/strict';
    import { mkdtempSync, mkdirSync, rmSync, statSync } from 'fs';
    import { tmpdir } from 'os';
    import { join } from 'path';
    import { ensureReviewsDir } from '../src/core/reviews.js';

    before(() => {
      tmp = mkdtempSync(join(tmpdir(), 'self-wiki-reviews-'));
    });

    after(() => {
      rmSync(tmp, { recursive: true, force: true });
    });

    test('ensureReviewsDir creates Reviews/ in a fresh vault', async () => {
      const vault = join(tmp, 'fresh');
      mkdirSync(vault, { recursive: true });
      await ensureReviewsDir(vault);
      assert.ok(statSync(join(vault, 'Reviews')).isDirectory());
    });

    test('ensureReviewsDir succeeds when Reviews/ already exists (idempotent)', async () => {
      const vault = join(tmp, 'pre-existing');
      mkdirSync(join(vault, 'Reviews'), { recursive: true });
      // Should not throw.
      await ensureReviewsDir(vault);
      assert.ok(statSync(join(vault, 'Reviews')).isDirectory());
    });

    test('ensureReviewsDir is safe on repeated calls (double invocation)', async () => {
      const vault = join(tmp, 'double-call');
      mkdirSync(vault, { recursive: true });
      await ensureReviewsDir(vault);
      await ensureReviewsDir(vault);
      assert.ok(statSync(join(vault, 'Reviews')).isDirectory());
    });

    test('ensureReviewsDir creates intermediate parents (recursive mkdir)', async () => {
      const vault = join(tmp, 'deep', 'nested', 'vault');
      // Deliberately do NOT pre-create the parent — recursive: true should handle it.
      await ensureReviewsDir(vault);
      assert.ok(statSync(join(vault, 'Reviews')).isDirectory());
    });

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `ensureReviewsDir` | The `vaultPath` argument is supplied by the caller (Phase 3 will pass it from `applyUserConfig`/`getVaultPath`). A malicious or malformed `vaultPath` could in theory point anywhere on disk. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-01 | Tampering | `vaultPath` argument | accept | The caller (Phase 3 self-review command) is internal trusted code. `vaultPath` originates from `paths.js#getVaultPath()` which itself is sourced from user-managed config. The helper does not perform path traversal beyond `join(vaultPath, 'Reviews')` — `path.join` does not allow `..` to escape conceptually but does not block it as raw bytes. Since the caller is trusted and the only operation is `mkdir`, the worst-case is creating a `Reviews/` directory in an unintended location — recoverable, not destructive. No data overwrite. |
| T-01-04-02 | Denial of Service | mkdir on caller-controlled path | accept | `mkdir(..., { recursive: true })` performs O(depth) syscalls. Caller-controlled depth is bounded by typical filesystem limits. No DoS surface beyond what `paths.js#ensureVaultDirs` already accepts. |
| T-01-04-03 | Tampering | Future writes to `Reviews/<*>.md` | mitigate (cross-phase) | Establish ownership rule in Phase 1: `src/core/reviews.js` is the sole sanctioned writer of `Reviews/<*>.md` (per ARCHITECTURE.md filesystem-ownership convention). Top-of-file comment in the new module documents this for Phase 3. |
</threat_model>
