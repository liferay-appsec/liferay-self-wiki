<objective>
Layer the auto-backfill cascade on top of slice 1. Missing monthlies
in the cycle window trigger `reportMonthOrchestrator(month, {internal:
true})` per missing month before the self-review prompt is built. The
monthly orchestrator itself already cascades to weeklies (Phase 2),
so the self-review case can result in a deep cascade (e.g.
4 monthlies × 4-5 weeklies each = up to ~20 claude invocations on
a fresh-vault cycle-end run).

Constraints:
- D-05: default-on; emit a preflight stderr summary so the user can
  Ctrl-C if surprised; non-interactive.
- D-05: single `hasClaudeCli` upstream gate before the cascade starts
  (no partial state from a mid-loop crash).
- D-06: existing monthlies are NOT regenerated (stale-monthlies-canonical);
  no `--refresh-monthlies` flag in v1.
- D-07: --dry-run NEVER invokes monthly synthesis (mirror Phase 2 D-15).
  Dry-run prints the envelope with placeholder text where monthlies
  are missing — already implemented in slice 1; this plan preserves
  that invariant.
- The soft-fail-to-dry-run path from slice 1 (REVIEW-08) MUST still fire
  before the cascade — when claude is missing AND user did NOT pass
  --dry-run, behavior is "stderr notice + print prompt, exit 0", not
  "exit 2". The cascade then never runs because we already returned.

Plan 03-06 also extends `reportMonthOrchestrator` to accept
`opts.internal === true` (mirroring `reportWeekOrchestrator`'s existing
plumbing). This is the minimum surgical change to report.js needed
for self-review to invoke it without producing duplicate "wrote ..."
stdout lines and without re-checking hasClaudeCli per iteration.

Purpose: Slice 2. After this plan a user can run `self-wiki self-review`
on a fresh vault and end up with all 4 monthlies + N weeklies + the
final review file produced from a single keystroke (caveat: 16+
claude invocations).
Output: Auto-backfill cascade + preflight summary + report.js
internal-flag plumbing + new tests.
</objective>
