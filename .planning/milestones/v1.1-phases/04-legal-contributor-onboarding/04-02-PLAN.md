<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → would-be contributor | CONTRIBUTING.md tells external readers (Liferay engineers who clone the repo) where to file issues and how to set up the dev environment. Wrong URL / wrong dev flow misroutes contributors. |
| CONTRIBUTING.md → CLAUDE.md | The Architectural contract section delegates the canonical rule text to CLAUDE.md. If the four rule names drift out of sync with CLAUDE.md, contributors get a confused signal about what the architecture actually requires. |
| `npm install -g .` → user's npm prefix | The regression-check task installs the CLI globally. This touches the user's npm prefix (typically `~/.npm-global/bin` or `/usr/local/bin`). Already a routine end-user operation — the regression check exercises a path the user already runs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Information disclosure | CONTRIBUTING.md committed text | mitigate | Acceptance criteria forbid `Liferay, Inc.`, `slack` (case-insensitive). No secrets, no internal Liferay URLs, no personal-vault content. Grep gates in Task 1 verify before completion. The only external URL is the public-shape `github.com/liferay-appsec/liferay-self-wiki/issues` — a repo-internal path under the same org that already has the source. |
| T-04-07 | Spoofing / phishing risk | GitHub Issues URL | mitigate | URL is hard-coded to the exact org/repo and verified by `grep -F "https://github.com/liferay-appsec/liferay-self-wiki/issues" CONTRIBUTING.md`. No URL shorteners, no third-party issue trackers, no redirection. |
| T-04-08 | Repudiation (rule names drift from CLAUDE.md) | CONTRIBUTING.md §Architectural contract | mitigate | The four rule names are checked verbatim by grep gates. The plan explicitly forbids per-rule glosses (D-ARCH-SECTION) — that prevents a future CLAUDE.md edit from silently invalidating CONTRIBUTING.md's prose. If CLAUDE.md renames a rule, CONTRIBUTING.md fails its acceptance criteria and the inconsistency is loud. |
| T-04-09 | Denial of service (regression check breaks dev environment) | npm install -g . | accept | This is the existing end-user install path that the user already runs (PROJECT.md / CLAUDE.md document it). The check exercises a path that is already in production use; no new install pathway is introduced. Severity: informational. |
| T-04-10 | Elevation of privilege (CONTRIBUTING.md tells contributors to run privileged commands) | Dev flow shell block | accept | The four dev-flow lines (clone, `npm install`, `npm link`, `self-wiki init`) are the same commands a contributor would run from any open-source repo's README. `npm link` requires no root if the user's npm prefix is set correctly (CLAUDE.md "Testing locally" already documents this is the supported flow). No `sudo`, no system-level changes recommended. Severity: low. |

All threats are `low` or `informational` severity; none meet the `high` block threshold.
