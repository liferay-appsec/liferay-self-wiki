<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| apache.org → repo | External canonical text is fetched via `curl` and written into `LICENSE`. The fetched bytes cross a trust boundary into the committed source tree. |
| repo → anyone with read access | LICENSE and NOTICE are visible to every Liferay engineer who clones `liferay-appsec/liferay-self-wiki`. Wrong text here creates IP / compliance risk. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information disclosure | LICENSE / NOTICE committed text | mitigate | Acceptance criteria forbid `Liferay, Inc.` (D-LEG-01-OVERRIDE) and `Christian Moura` (prior MIT identifier). Grep gates in Task 1 and Task 2 verify before completion. No secrets, no internal URLs, no personal-vault content leaks into either file. |
| T-04-02 | Tampering / IP risk | LICENSE | mitigate | Apache 2.0 text fetched ONLY from canonical https://www.apache.org/licenses/LICENSE-2.0.txt. Integrity verified by: (a) `head -1 LICENSE` matches `Apache License`, (b) appendix placeholders `[yyyy]` / `[name of copyright owner]` present, (c) length sanity (`wc -l LICENSE` ~202 lines). Reformatted Linux-distro copies are explicitly forbidden (would break GitHub's license detector). |
| T-04-03 | Tampering (pipe-execute attack via remote fetch) | curl pipeline | mitigate | `curl` writes the response to a file (`-o LICENSE`), it does NOT pipe into a shell. No `curl ... \| bash` or `eval $(curl ...)` pattern is used anywhere in this plan. The fetched bytes are inert text. |
| T-04-04 | Repudiation (wrong license attribution after the fact) | NOTICE | accept | Sole-original-author re-license is per D-NO-MIT-NOTE; git history preserves the prior MIT LICENSE for any audit. No additional mitigation required. Severity: low. |
| T-04-05 | Denial of service (curl fails, blocks the phase) | apache.org fetch | mitigate | If the fetch fails the task stops and reports — does NOT silently substitute. Operator can rerun once the network is back, or copy from a known-good locally-cached canonical file (the failure is loud, not silent). Severity: low, recovery is trivial. |

All threats are `low` or `informational` severity; none meet the `high` block threshold.
</threat_model>
