# Roadmap: self-wiki — Liferay Self-Review Milestone

## Overview

Three phases build the self-review capability bottom-up. Phase 1 lays the
config and vault foundation so the tool understands Liferay's cycle calendar.
Phase 2 adds the monthly themed-synthesis report — the intermediate narrative
layer that makes a 4-month review tractable. Phase 3 delivers the headline
artifact: `self-wiki self-review` produces a Liferay-form-shaped draft that
the user pastes directly into the review form.

## Phase Details

### Phase 1: Cycle Config & Vault Scaffold
**Goal**: The tool knows about Liferay's review cycle calendar, can compute cycle boundaries from a date, and scaffolds the Reviews/ folder for both new and pre-existing vaults.
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: CONFIG-01, CONFIG-02, CONFIG-03, SCAFFOLD-01, SCAFFOLD-02
**Success Criteria** (what must be TRUE):
  1. Running `self-wiki init <vault>` on a fresh vault produces a `.self-wiki/config.json` with a `review` section containing `cycleEndMonths: [5, 9, 12]`, `lastReviewedAt: null`, and `lastReviewedCycle: null`, and creates a `Reviews/` directory alongside `Reports/`, `Tickets/`, and `Components/`.
  2. Running `self-wiki self-review` on a pre-existing (pre-milestone) vault with no `Reviews/` directory auto-creates the folder and the `review` config section without erroring or warning — the config migration is transparent.
  3. A developer can call the cycle-boundary helper with any date and `cycleEndMonths` and get back `currentCycleStart`, `currentCycleEnd`, and `previousCycle` values that are correct for Liferay's May / September / December schedule — confirmed by manually varying the input date across cycle boundaries.
  4. Changing `cycleEndMonths` in vault config to `[6, 12]` (semi-annual) causes the cycle helper to compute boundaries for a 6-month cadence, with no code changes required.

### Phase 2: Monthly Report
**Goal**: Users can generate a themed monthly synthesis report for any calendar month, with deterministic metrics computed in code and narrative prose through `claude -p`, following the same patterns as the weekly report.
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: MONTH-01, MONTH-02, MONTH-03, MONTH-04, MONTH-05, MONTH-06
**Success Criteria** (what must be TRUE):
  1. User can run `self-wiki report --month 2026-04` and receive a themed monthly report at `Reports/2026-04.md` containing a deterministic metrics block (session counts, distinct tickets, components touched, active days — computed in code) followed by model-synthesized prose about themes, threads, and recurring tickets.
  2. Re-running the same command overwrites the prior file and adds a `<!-- regenerated YYYY-MM-DD -->` marker at the top; the file is reproducible from the same daily-log inputs.
  3. Running `self-wiki report --month <YYYY-MM>` for a partial month (e.g. the current in-progress month, or a month where the vault was freshly installed) completes without error and includes a header note describing the partial window — it does not refuse to run.
  4. Running `self-wiki report --month <YYYY-MM> --dry-run` prints the full synthesis prompt to stdout without invoking `claude -p`, matching the existing `report --dry-run` pattern; if `claude` is missing from PATH, the command degrades to dry-run mode and prints a notice instead of failing.

### Phase 3: Self-Review Report
**Goal**: Users can run `self-wiki self-review` at the end of a Liferay review cycle and receive a draft at `Reviews/<YYYY>-cycle<N>.md` shaped to the three Liferay review questions, with accomplishments tagged by Liferay values, sourced from monthly reports, weekly reports, and topic pages.
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: REVIEW-01, REVIEW-02, REVIEW-03, REVIEW-04, REVIEW-05, REVIEW-06, REVIEW-07, REVIEW-08, REVIEW-09
**Success Criteria** (what must be TRUE):
  1. User can run `self-wiki self-review` immediately after a Liferay cycle ends and receive a draft at `Reviews/<YYYY>-cycle<N>.md` with three top-level sections matching Liferay's three review questions, accomplishments in section 1 each explicitly tagged with one or more of the five Liferay values in the format `- **<accomplishment>** — <Value>[, <Value>]`.
  2. Review-window boundary resolves correctly in all three modes: `--since 2026-01-15` pins the start date; omitting `--since` on a second run uses the `lastReviewedAt` date stored in vault config from the prior run; omitting both on a first-ever run falls back to the most recently completed cycle from `cycleEndMonths`.
  3. On successful generation, vault config is updated with `review.lastReviewedAt` (today's ISO date) and `review.lastReviewedCycle` (e.g. `2026-cycle1`), so the next `self-wiki self-review` run defaults to "since the last one I generated" without any manual tracking.
  4. The generated draft includes a "Sources" footer listing which monthly, weekly, and topic files were consumed, so the user can spot-check provenance and identify which notes drove each section.
  5. Running `self-wiki self-review --dry-run` prints the synthesis prompt without invoking `claude -p`; `--cycle <YYYY-cycleN>` and `--last-cycle` flags work for explicit window control; missing `claude` degrades to dry-run with a notice rather than a hard failure.
