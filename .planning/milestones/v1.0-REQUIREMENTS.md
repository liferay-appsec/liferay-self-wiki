# Requirements: self-wiki — Liferay Self-Review Milestone

**Defined:** 2026-05-07
**Core Value:** A Claude Code session leaves behind a useful daily log, a per-ticket history, and a weekly report — without the user typing a single per-session command. This milestone extends that to: *a 4-month run of work leaves behind a draftable Liferay self-review.*

## v1 Requirements

Requirements for the self-review milestone. Brownfield: v0.1 capabilities are listed under "Validated" in PROJECT.md and are not repeated here.

### Monthly Report

A new themed-synthesis report. Building block for the self-review.

- [x] **MONTH-01**: User can run `self-wiki report --month <YYYY-MM>` to generate a themed monthly report from weekly reports + topic pages within that calendar month
- [x] **MONTH-02**: Monthly report uses a separate, versioned prompt template at `src/templates/prompts/monthly-report.md`. The prompt produces *themes, threads, and recurring tickets* — not a session-by-session log (that's the weekly's job)
- [x] **MONTH-03**: Monthly report writes to `Reports/<YYYY-MM>.md`; re-running on the same month overwrites the prior file (with a `<!-- regenerated YYYY-MM-DD -->` marker at the top)
- [x] **MONTH-04**: Monthly report degrades gracefully when fewer than 4 weeks of data exist in the window (partial month, just-installed vault, end of month) — emits what it has with a header note about the partial window
- [x] **MONTH-05**: Deterministic metrics in the report (session counts, distinct tickets, components touched, total active days) are computed in code from the parsed daily logs; only narrative prose goes through `claude -p`. Same split as the weekly report.
- [x] **MONTH-06**: `--dry-run` prints the synthesis prompt without invoking `claude -p` (matches existing `report --dry-run` pattern)

### Self-Review Report

The milestone's headline artifact. Liferay-form-shaped quarterly draft.

- [x] **REVIEW-01**: User can run `self-wiki self-review` to generate a Liferay self-review draft at `Reviews/<YYYY>-cycle<N>.md`
- [x] **REVIEW-02**: Review-window boundary resolves with precedence: explicit `--since <YYYY-MM-DD>` flag → vault config `review.lastReviewedAt` → most recent completed cycle from `review.cycleEndMonths` calendar. First match wins.
- [x] **REVIEW-03**: Output is shaped to Liferay's three review questions, each as a top-level section:
  1. *What have you accomplished since your last review? What work are you proud of?*
  2. *Since your last review, what is something you would have done differently in your work?*
  3. *What is your current area of focus as you "Grow & Get Better", and how will that positively impact your work?*
- [x] **REVIEW-04**: Section 1 (accomplishments) lists each item explicitly tagged with the Liferay value(s) it embodies. Format: `- **<accomplishment>** — <Value>[, <Value>]`. Values are chosen from the fixed set: Produce Excellence, Lead by Serving, Value People, Grow & Get Better, Stay Nerdy.
- [x] **REVIEW-05**: Self-review consumes monthly reports (primary narrative source), weekly reports (secondary detail), and topic pages from `Tickets/` and `Components/` (ticket-by-ticket ground truth). It does NOT consume raw daily logs — too granular for a 4-month window.
- [x] **REVIEW-06**: Self-review prompt template lives at `src/templates/prompts/self-review.md`. Iterable like the weekly prompt. Constrained to evidence in the source artifacts — no invention (same rule as weekly).
- [x] **REVIEW-07**: On successful generation, self-review writes back `review.lastReviewedAt: <ISO date>` and `review.lastReviewedCycle: <YYYY-cycleN>` to vault config (`<vault>/.self-wiki/config.json`). Subsequent runs default to "since the last one I generated."
- [x] **REVIEW-08**: `--dry-run` prints the synthesis prompt without invoking `claude -p`. `--since`, `--cycle <YYYY-cycleN>`, and `--last-cycle` flags supported for explicit window control.
- [x] **REVIEW-09**: A "Sources" footer lists which monthly/weekly/topic files fed the synthesis, so the user can spot-check provenance and refine the underlying notes if a section is weak.

### Vault Config & Cycle Calendar

- [x] **CONFIG-01**: Vault config (`<vault>/.self-wiki/config.json`) gains a `review` section seeded with: `{ "cycleEndMonths": [5, 9, 12], "lastReviewedAt": null, "lastReviewedCycle": null }`. New vaults get this from `init`; existing vaults get migrated on first `self-wiki self-review` invocation.
- [x] **CONFIG-02**: `cycleEndMonths` is user-editable (e.g. semi-annual cadences become `[6, 12]`). Defaults match Liferay's current 4-month cadence — May / September / December.
- [x] **CONFIG-03**: Helper utility (`src/core/cycles.js` or similar) derives `currentCycleStart`, `currentCycleEnd`, and `previousCycle` from a date + `cycleEndMonths`. Used by self-review when no `--since` and no `lastReviewedAt`.

### Vault Scaffold

- [x] **SCAFFOLD-01**: `init` creates a `Reviews/` directory in new vaults (parallel to `Reports/`, `Tickets/`, `Components/`)
- [x] **SCAFFOLD-02**: First `self-wiki self-review` run on a pre-existing (pre-milestone) vault auto-creates `Reviews/` if missing — no error, no warning, just create-and-write

### Trend & Analysis

- **TREND-01**: Year-over-year self-review trend report — read prior `Reviews/` files, surface "what changed since last cycle"
- **TREND-02**: Per-value coverage metric — count which Liferay values were tagged in section 1 across cycles, surface gaps ("you haven't claimed Lead by Serving in 3 cycles")

- **TOOL-01**: Markdown-to-Liferay-form export helper (clipboard-ready section-by-section copy, since the actual form is a web app with separate fields)

## Out of Scope

Explicit exclusions. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| API integration with Liferay's actual self-review form | Manual paste-in works; integrating with internal Liferay HR is out of personal-tool scope and likely against IT policy |
| Multi-user / shared-vault aggregation | Personal tool; one engineer per vault |
| Ratings, quantitative scoring, percentile rankings | Self-reviews are qualitative; metrics on engineering work are misleading at this granularity |
| npm registry publish | Clone + `npm install -g .` distribution model stays |
| Real test suite | v0.1 has none; this milestone keeps it that way unless a regression bites hard |
| `obsidian-cli` integration | Direct `.md` writes only; wikilinks work in raw markdown |
| Importing other companies' review processes | Prompts are Liferay-specific by design; users at other companies fork |
| Pid liveness / daemon | Sessions framed entirely by hooks; if state freshness becomes a problem, fix the hook |
| Self-review consuming raw daily logs | Too granular for 4-month windows; monthly reports are the right intermediate |
| Daily report (in addition to weekly + monthly) | Daily logs themselves are already the daily artifact; no synthesis layer needed below weekly |
